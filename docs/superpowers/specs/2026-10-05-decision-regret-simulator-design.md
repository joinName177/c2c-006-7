# 决策后悔模拟器设计说明

## 目标

构建一个完全在浏览器运行的 Vue 3 决策辅助应用。用户描述一个重大决策、添加 2–4 个选项并分配价值观权重，应用生成 1 年、5 年、10 年的后悔预演、后悔曲线和“最不后悔选项”建议。结果用于促进思考，不替代专业意见。

## 技术与工程约束

- Vue 3、TypeScript、Vite、Vitest；仅使用原生 CSS，曲线使用内联 SVG。
- 不调用在线 AI；文本与评分均由透明、可重复的本地规则生成。
- 项目拥有独立 Git 仓库、README、Dockerfile、docker-compose.yml 和 Nginx 单页应用配置。
- 生产镜像默认映射到宿主机端口 `8106`。
- 采用核心层、端口层、适配器层、界面层四层结构。

## 产品范围

### 决策录入

用户输入决策标题、背景说明和 2–4 个选项。每个选项包含名称、简述，以及稳定、成长、自由、金钱四个维度的预期影响值，范围为 -5 到 +5。界面提供“是否辞职”和“是否搬家”两个可一键载入的示例，但不会替用户补充事实。

### 价值观权重

用户使用滑块为稳定、成长、自由、金钱分配相对权重。界面实时归一化为 100%，允许原始权重相同；全部为零时阻止计算并提示至少关注一个价值维度。用户也可从“稳健优先”“成长优先”“自由优先”“均衡考虑”预设开始调整。

### 后悔预演

规则引擎基于每个选项的维度影响、价值权重、时间跨度和机会成本，生成 1 年、5 年、10 年三张卡片。每张卡包含可能遗憾、触发条件、可逆性和一个降低后悔的行动。文本来自维度化模板，并插入用户选项名称和高权重价值；不伪造概率或外部事实。

### 后悔指数

每个时间点的指数为 0–100：四个价值维度的负向偏差按归一化权重和时间系数计分，不可逆性作为独立的第五个贡献项（0–8 分）参与加总。所有排序、差额与并列判定一律使用未舍入的精确值；展示时细项四舍五入到 0.1、总分到整数，并给出“舍入 / 截断余量”行，使细项展示值之和加余量精确等于显示分。越界截断到 0–100 并标记，截断差额同样进入余量行。最终给出评分拆解，确保建议可解释。

### 后悔曲线与建议

SVG 曲线在同一坐标系绘制所有选项的 1/5/10 年后悔指数，支持图例开关和点位详情。总后悔指数使用 1 年 30%、5 年 40%、10 年 30% 加权；最低者成为“最不后悔选项”。若前两名精确总分差距小于 5 分，应用不做强结论，而提示两个选项接近并建议补充信息；精确差小于 0.05 分（整数口径不可见）判实质并列。

### 方案比较

排名和整数总分会掩盖两个方案的真实差距来源，结果页支持任选两个方案生成比较：

- **时间拆解**：按 1 年、5 年、10 年分别列出五个贡献项（稳定、成长、自由、金钱、不可逆成本）的双方分数与差额，并提供总分层面的 30/40/30 汇总。每项可展开“判断依据”：两端影响值、本次推演的归一化权重、时间系数，或两端可逆性与系数。
- **方向口径**：比较由纯函数 `compareOptions(analysis, baseId, otherId)` 计算，差额恒为对照减基准。反转方向只交换两个 id，全部符号、受益方与文案随之自动反转，界面不存在第二套理由。选择同一方案返回空态并如实说明。
- **舍入口径**：差额展示精确到 0.1 分（另附整数差），判定只用精确值。整数总分相同但精确差达到 0.05 以上时明示整数口径在掩盖差异；精确差 < 0.05 判并列。每一时间点与汇总表都有“舍入 / 截断余量”行，保证细项差额 + 余量 = 展示差额，细项、差额与最终排名严格对得上。
- **抵消呈现**：贡献按绝对差额降序，绝对值 ≥ 0.5 分的项全部展示，更小的差异弱化但不隐藏。正负两侧各自达标的最大贡献强制成对呈现为“抵消对”，摘要先报毛额（两侧幅度之和）再报净额；时间跨度内的抵消在对应年份卡内另行标注。
- **分析版本绑定**：每次推演带唯一 id、时间戳与由全部评分输入稳定算出的签名。比较只保存对某次分析 id 的引用；输入变化后比较标记过期但仍可查看旧依据，重新推演后仅当两个方案仍存在时续绑，否则结束。删除比较中的任一方案立即清除比较。
- **保存与打印**：保存案例时比较引用（两端方案 id、分析 id、时间）与完整分析快照一并持久化；加载时校验分析 id 与方案 id 都对得上才恢复，旧版本案例自然为空比较。打印报告包含比较对象、分析编号、输入签名、细项差额与依据（依据在打印时强制展开）。

### 保存与导出

用户可保存多个决策案例到 localStorage，支持重命名、复制和删除。结果页提供浏览器打印，输出决策背景、价值权重、评分拆解、预演卡和曲线。

## 架构

- `src/core`：领域模型、输入校验、权重归一化、后悔评分（`regret-engine.ts`）、比较拆解（`compare-service.ts`）、预演模板、建议排序。
- `src/ports`：决策案例仓储端口、打印端口。
- `src/adapters`：localStorage 仓储、浏览器打印适配器。
- `src/ui`：Vue 分步表单、结果仪表板、SVG 曲线和原生 CSS。

核心函数输入完整决策模型并返回不可变分析结果，不读取浏览器状态。界面负责收集事实和显示解释，不直接计算指数。

## 状态与数据流

流程为“描述决策 → 编辑选项 → 调整权重 → 生成预演 → 查看建议”。输入变化后旧结果标记为过期，用户点击重新计算才覆盖结果。仓储解析失败时保留当前编辑内容并显示非阻塞提示；删除案例前需要二次确认。

## 交互与视觉

整体采用“思考档案室”风格：暖灰纸张、墨黑文字、蓝紫和琥珀色曲线，使用编号、批注和坐标纸细节营造审慎氛围。桌面端为左侧步骤导航与右侧工作区，移动端为顶部进度条。评分同时展示数字、文字解释和拆解，不以单一颜色传达好坏。

## 安全与边界提示

当标题或背景包含明显医疗、法律、投资等高风险关键词时，结果页追加领域专业咨询提示，但仍允许用户使用自我反思工具。任何结论都使用“建议进一步考虑”而非命令式措辞。

## 测试与验收

- 单元测试覆盖权重归一化、全零权重、分数边界、时间权重变化、并列建议、预演文本和风险提示。
- 比较测试覆盖：方向反转后每项差额精确变号且受益方互换、各时间点与汇总层的细项+余量对账、整数掩盖提示、实质并列、抵消对不被省略、影响/权重/可逆性依据完整、同一方案空态、分析版本续绑与方案删除失效。
- 组件级测试覆盖选项数量边界、步骤校验、结果过期标记、案例保存/恢复、比较选择/反转/结束和方案切换。
- 验收需通过 `npm test`、`npm run build`，并人工检查曲线可读性、移动布局、打印预览及 Docker 构建。

## 非目标

不预测真实未来、不生成成功概率、不提供医疗、法律或投资结论，不接入大语言模型，不实现账号或云同步。
